# 原生拖放

设置中的「拖放」包含两个独立开关，默认开启，保存失败时保留旧值：

- 拖入链接和链接文件。
- 将已完成文件拖到其他应用。

拖入只打开新建下载草稿，由用户确认后才开始下载；不会自动执行或打开拖入的文件。多文件 `.txt` / `.url` 导入在后台合并、去重和验证，任一文件错误则整批拒绝，合计上限 2 MiB、最多 1000 个文件，并沿用应用批量链接数限制。目录、符号链接、可执行文件等不会作为链接文本读取。

macOS 原生接收浏览器 pasteboard 的 `public.url` 和 URL 纯文本；保留 winit 的文件拖入。Windows 使用 OLE `IDropTarget`，支持 `UniformResourceLocatorW`、`UniformResourceLocator`、`CF_UNICODETEXT` 和 `CF_HDROP`；停用 winit 原先只接收文件的目标，避免重复注册。URL 只接受无用户名/密码的 HTTP(S)/FTP(S)，不会把 `.webloc` 文件读取称作原生 URL 拖入。

拖出方式：在卡片或表格视图拖动已完成任务。拖动已勾选任务时，将所选任务作为一批；其中包含未完成、缺失、目录或符号链接时整批拒绝。最多 1000 个已完成普通文件，交给系统之前再次检查。传给系统的操作类型固定为 Copy，应用不会因拖出成功删除或移动原始文件。

开发验证包括 URL 格式与凭据拒绝、拖出文件状态/普通文件检查和原文件保留、多文件导入原子性与总预算；macOS 使用独立 NSPasteboard 验证真实 URL/纯文本格式读取，不碰系统通用剪贴板。Windows 的 OLE 模块在独立 x86_64-pc-windows-msvc 工程做类型检查，该检查不是完整 Windows 应用构建或实机拖放。

保留的人工验收：浏览器链接拖入后的确认流程、Finder/Explorer 拖出单选和多选、复制后源文件仍存在、开关关闭后的拒绝行为、Windows 安装包中的 COM 注册与各浏览器兼容。原生手势未通过这些解析器和编译检查自动证明。
