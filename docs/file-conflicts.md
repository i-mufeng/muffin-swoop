# 同名文件处理

设置 → 同名文件。普通 HTTP(S)/FTP(S) 文件与媒体下载使用同一个持久化策略；旧配置缺少此设置时为「每次询问」。本项按用户指定的 IDM 式操作方式实现，默认询问是本项目的明确产品选择。

| 设置 | 行为 |
| --- | --- |
| 每次询问（默认） | 保留原文件，任务显示「等待确认」，弹出覆盖、重命名、取消。 |
| 自动重命名 | 使用 `名称 (1).扩展名`、`名称 (2).扩展名` 等可用名称。 |
| 自动覆盖 | 完整下载到同目录临时文件，验证成功且原文件未变后再替换。 |
| 跳过 | 保留原文件，任务转为暂停/已停止，可稍后处理。 |

弹窗不勾「记住选择」时只处理当前任务；勾选后保存为默认策略。点击取消或关闭弹窗不会删除文件或任务记录。设置保存失败会留在弹窗并显示错误，不继续执行覆盖。已有等待确认任务仍需单独处理，更改默认策略不会批量授权它们。

等待确认的文件任务不占队列下载槽位，其他任务可以继续；等待确认状态随历史保存，重启后重新展示。界面隐藏时会唤回，多个询问依次处理，当前窗口不会因新任务到来换成另一文件。存在未处理询问时不启动全部完成后的退出/关机倒计时。

覆盖不是先删除旧文件。普通文件和媒体均暂存下载并检查原文件的规范路径、大小、SHA-256 与文件信息；失败、取消或下载期间用户编辑原文件时保留原件。目录、符号链接不作为可覆盖的普通文件。HTTP(S)/FTP(S) 覆盖暂停后可安全重新下载暂存内容；媒体取消后重新开始会重新应用当前策略。文件任务的周期同步仍使用自己的已完成文件指纹，不受新任务同名默认策略改变。

最终发布时先把实际目标移入同目录唯一恢复文件，再校验并以不覆盖方式发布新文件；这段过程不是跨文件原子事务。外部程序在发布瞬间保存的新目标优先保留。若恢复时目标也已被占用，原件留在 `.swoop-recovery-*` 或 `.swoop-media-recovery-*.bak`，错误会显示路径；不能把恢复失败当普通取消而隐藏。文件引擎在移动原件前把恢复路径记入 SQLite，重启后按指纹恢复；保留恢复文件期间不会移除该任务记录。删除未确认、未完成覆盖任务不会删除尚未归属它的原文件。

同一应用的 HTTP(S)/FTP(S) 与媒体 worker 共用目标占用登记，直到写入与发布真正结束才释放；已暂停文件下载的部分文件也保留任务归属。被其他任务占用时选择重命名，或结束并移除相关任务记录后再处理，不能用覆盖抢占正在写入的目标。自动重命名同时避让磁盘文件与尚未发布的媒体目标；最终发布仍检查晚到的外部文件。

## 未完成的临时文件

新的 HTTP(S)/FTP(S) 下载把数据写在目标旁的 `<文件名>.swoop`，下载完成后再以不覆盖方式改名为目标文件名，未完成的文件不会被误当成成品打开。同名判断只看目标本身：另一个未完成任务的 `.swoop` 不算同名文件，新任务直接顺延为 `名称 (1).扩展名`。下载期间外部程序占用了目标名时，完成后同样顺延编号，不覆盖用户文件。改名后、记录落盘前退出的任务，重启后识别为已发布。升级前已开始的任务（库中 `part_file` 为 0）继续直接写目标文件。覆盖下载仍走上面的同目录暂存与安全发布，不用 `.swoop`。

在界面中移除未完成的任务（下载中、暂停、失败）会同时删除已下载的部分；运行中的任务在退出、关闭句柄后再清理一次自己创建的 `.swoop`。已完成的任务只移除记录，保留文件。

CLI 可用 `conflict-policy` 查询/设置，HTTP(S)/FTP(S) 用 `resolve`、媒体用 `media-resolve` 处理单个任务；具体参数见 [CLI 说明](cli.md)。CLI 没有交互式确认输入，不会因终端无人值守而把询问视为同意覆盖。

## 验证边界

核心本地 HTTP/FTP 回归覆盖默认询问、队列不阻塞、重启恢复、改名、跳过、全局覆盖、相同内容、覆盖中暂停/重启、询问/下载期间编辑、部分文件归属及媒体目标占用。媒体库使用真实 FFmpeg 验证覆盖成功、取消、缺片、用户修改与最终产物；应用控制测试覆盖持久化失败和两类任务的冲突处理。

Windows 实机仍待执行，macOS 原生弹窗按钮与后台唤回尚需桌面交互验收；自动化控制通道和库测试不代替这些实机项目。对标总表见 [IDM 功能矩阵](idm-parity.md)。
